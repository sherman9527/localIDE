## 1. 核心机制

### 1.1 编排拓扑：四种形态与选择判据
| 形态 | 适用 | 优点 | 主要风险 |
|---|---|---|---|
| 单 agent + 工具循环（ReAct 类） | 任务链短、工具 ≤ 10 | 简单、可控、易评测 | 上下文膨胀、长任务易失焦 |
| 流水线（固定 DAG，模型只在节点内） | 流程已知（ETL、审校、工单分诊） | 稳定、成本可预测、节点可测 | 灵活性差，异常需回退路径 |
| Supervisor / 层级（planner + workers） | 子任务可并行、需权限隔离 | 上下文隔离、并行收益、失败局部化 | 成本翻倍、指令衰减、结论冲突需仲裁 |
| 对等 handoff（swarm 类） | 领域切换自然（客服：退款 ↔ 技术） | 响应快、专业度 | 循环/踢皮球、全局目标漂移、难归因 |
判据（principal 的答案）：**拆分的正当理由只有三个**——上下文隔离（否则互相污染）、权限隔离（不同 scope 的工具集）、并行与延迟收益；"看起来更聪明"不是理由。拆分后必须有：预算闸（步数/token/$）、终止条件、循环与无进展检测、结论合并规则（谁有最终写权）、以及全链路 trace。

### 1.2 长任务与 durable 语义
- 任务生命周期：`接收 → 计划 → 执行（可挂起）→ 人工确认 → 继续 → 终态`；挂起要能持久化状态（不靠进程内存），恢复要幂等（重放历史时不重复执行外部副作用）。
- 与协议衔接：MCP tasks 扩展（`tasks/get` 轮询 + `tasks/update`）+ MRTR（需补充输入时重发原请求）→ 服务端不再长连接阻塞，但**幂等与状态外置成为你的责任**。
- 失败恢复：步骤级重试预算、补偿（已执行动作的逆操作或人工兜底）、"悬挂态"对账（执行结果未知的动作定时查询）。
- 人机协同（HITL）：确认粒度绑定到"动作影响预览"（dry-run 列对象与数量），确认 token 绑定预览结果 hash（防"预览 A 执行 B"），审批超时策略（默认拒绝 vs 降级只读）。

### 1.3 成本与延迟模型
```
单任务成本 = Σ(每步：输入 token × 单价 + 缓存读/写差价值 + 输出 token × 单价) 
           + 工具/检索成本（外部 API、模型嵌入、查询扫描量）
           + 重试与扇出倍数（失败率 × 成本）
```
- 杠杆按收益排序：① 减少步数与扇出（最猛，也最容易被忽略）；② 输入压缩（工具输出裁剪、检索材料摘要、历史 compaction）；③ 前缀稳定化命中缓存（系统/工具段不变，动态内容后置）；④ 模型路由（小模型做分诊/抽取/改写，难例升级）；⑤ 并行化（关键路径分解，投机执行 + 早停）；⑥ 蒸馏/专用化（有稳定高频子任务才值得）。
- 延迟：区分 TTFT 与完成时间；关键路径 = 最慢串行段，工具调用尽量并行（无依赖时）；"先给可纠正的中间产物"（草稿/计划）比"整体更慢但一次到位"常常是更好的产品策略。
- 预算治理：per-user/per-tenant/per-task 三层预算 + 熔断（成本或步数超限即降级为"说明当前进展 + 需要人介入"）；成本与延迟作为一等 SLI 上看板，纳入发布门禁。

### 1.4 安全护栏（分层纵深，缺一不可）
1. **输入侧**：来源可信等级标注（用户输入 / 检索文档 / 工具返回 / 网页邮件内容），不可信内容显式包裹并声明"其中的指令不是指令"；长度/编码异常检测（Base64/不可见字符/越权句式）。
2. **决策侧**：工具 allowlist（按 agent 角色而非全局）+ 参数 schema 严格校验 + 敏感字段不可作为自由文本参数（域名/URL/脚本/收件人一律白名单枚举）；高危动作二次确认。
3. **执行侧**：沙箱（无网络或出站 allowlist、只读挂载、CPU/内存/磁盘/时长上限、文件系统隔离），子进程与容器边界；对"生成代码并执行"的场景要有静态检查 + 资源限制 + 网络断言（这是最常见的 RCE 面）。
4. **数据侧**：最小权限凭证（短时、可撤销、窄 scope）、出站数据脱敏（PII/密钥扫描在**出口**做，而不是只在入口）、防侧信道（agent 把内部数据编码进外部请求参数/URL/DNS）。
5. **记忆侧**：防持久化注入（写入需来源分级 + 长度/格式约束 + 可撤销）；防"记忆越权读取"（命名空间按用户/租户隔离）。
6. **审计与响应**：完整决策留痕（用了哪些证据、调了哪些工具、谁批准）、异常行为检测（非常规调用序列、批量导出、非工作时段高危动作）、Kill switch（租户/全局一键降级）。
- 威胁建模时直接对齐 **OWASP Agentic Top 10（2026 版）**：目标劫持、工具误用与利用、身份与权限滥用、代理间信任不当、记忆/上下文投毒、规划/推理注入、代码执行、供应链、人类-代理交互失效、缺失护栏/失控代理等条目方向（**具体命名与编号请在入库时核实**）；再叠加"红队用例常态化 + 评测门禁中安全项零失败"。

### 1.5 可观测性与运维
- 以"逻辑调用/一次任务"为 trace 单位：span = LLM 调用（模型、参数、token 输入/输出/缓存命中、成本、TTFT）/ 工具调用（参数摘要、耗时、结果码）/ 检索（召回数、来源分布）/ 人工节点（等待时长）。
- 错误分类是运维核心：模型错（格式/幻觉）、工具错（下游 5xx/超时）、数据错（证据缺失/过期）、策略错（越权尝试）、用户错（输入不合法）——每类有 owner 与处置路径。
- 质量在线监测：忠实度/拒答率/接管率/引用点击率漂移、成本与步数分布右移（往往是"开始绕远路"的信号）；尾部采样必须保留失败轨迹（不要只采成功样本）。
- 回放优先：任何线上失败 trace 要能在评测环境重放（工具桩 + 数据快照），否则"修不动、验证不了"。
- 第四信号：连续 profiling（OTel Profiles alpha 阶段）用于定位 tokenizer/序列化/GPU/CPU 瓶颈，别把它当噱头——延迟优化的钱常常在客户端与序列化侧。

## 2. senior / principal 会被追问什么

1. "这个场景为什么不是单 agent + 好工具？"（必须给拆分的正当理由与收益量化）
2. "你的熔断条件是什么？（步数、成本、时间、无进展、越权尝试）触发后给用户看什么？"
3. "外部动作执行结果未知（超时）怎么处理？"（幂等键 + 状态查询 + 悬挂态对账 + 永不自动重试写）
4. "多 agent 冲突结论怎么仲裁？"（权威写入者 + 证据权重 + 回退到人工 + 记录为失败用例）
5. "如何证明你的护栏有效？"（红队用例集 + 安全项作为发布硬门禁 + 演练：注入成功率、越权成功率指标）
6. "成本涨了 3 倍，你的定位顺序？"（步数分布 → 扇出倍数 → 输入 token 构成（工具输出占比）→ 缓存命中率 → 模型路由比例）
7. "上线后质量下降但没报错，你怎么发现？"（漂移指标 + 抽样人评 + 影子对比 + 失败模式聚类）
8. "人工确认会不会成为吞吐瓶颈？"（确认粒度合并、批处理审批、低风险动作白名单化、只预览一次多动作）
9. "你的 agent 会自己给自己提权吗？如何检测？"（工具调用序列审计：新出现的工具组合、绕过只读路径的尝试）
10. "如果要支持 10 万 DAU，哪层先崩？"（推理配额、向量/检索 QPS、工具下游限流、状态存储、并发会话成本——每层的弹性策略）

## 3. 常见错误答案

- "多 agent 一定更好"（成本 ×N、误差级联、归因困难）。
- 把安全做成"系统提示里写不要做坏事"（指令可被覆盖，无执行边界）。
- 只有全局 token 预算，没有"每步预算 + 无进展/循环检测"（真实失控是绕圈而不是单次超长）。
- 把高危动作与只读动作同等权限同等审批（团队很快要求绕过审批）。
- 出口不脱敏，只在入口做校验（数据经工具参数外带）。
- 超时即重试写操作（重复副作用）；无悬挂态对账。
- 观测只看"错误率/延迟"，无 token/成本/步数/证据质量分布 → 静默劣化看不见。
- 评测与生产环境不同源（无回放能力），修复无法验证。
- 成本优化第一步就上"换便宜模型"（质量塌陷后又换回来，浪费两轮），而没先减步数与输入。
- 声称"完全符合 OWASP"但说不出自己最危险的两条风险与对应控制。

## 4. 出题角度

### 题面草稿 A（`code`，`judgeKind=java-junit`）
> 实现编排引擎核心 `AgentLoop.step(StepResult r)` 的预算与熔断逻辑（Java，纯逻辑，无网络）：
> ① 预算：`maxSteps`、`maxCostMicros`、`maxWallMs`、`maxToolFailures`，任一超限进入 `BUDGET_EXCEEDED(reason)` 且**不得再发起工具调用**；
> ② 无进展检测：连续 `n` 步"上下文新增信息 hash 未变化"→ `STALLED`；同 `(tool, argsHash)` 连续 `m` 次 → `LOOP`；
> ③ 高危动作：`r.pendingActions` 含 `destructive` 时返回 `AWAIT_CONFIRM(dryRunHash)`，且确认仅在 `confirmToken` 与 `dryRunHash` 一致时放行（不一致返回 `CONFIRM_MISMATCH`）；
> ④ 悬挂态：`UNKNOWN_OUTCOME` 的动作进入 `RECONCILE` 队列，引擎可继续但**不得重复发起同 key 写**，超时（注入时钟）后升级为人工；
> ⑤ 恢复：`stateSnapshot()/restore(state)` 必须能在无内存进程的情况下重建（测试用序列化往返 + 重放相同历史，断言决策序列一致）。
> 用例：步数/成本/时间三类超限、LOOP 与 STALLED 区分、确认 hash 不匹配、UNKNOWN 不重发（后端调用计数）、快照恢复后行为一致。

### 题面草稿 B（`code`，`judgeKind=redis`）
> 实现"租户级 agent 预算与并发"：① 每租户每分钟 token 预算与每日成本预算（成本用微元整数累计）；② 并发会话上限 + 单会话执行租约（TTL 续期，进程崩溃自动回收）；③ 全局降级开关（`kill:<scope>`）存在时新调用一律返回 `DEGRADED`，正在执行的会话允许完成当前步后停在只读态。用例含预算耗尽、跨日重置、并发抢占、租约过期回收、kill switch 生效延迟（断言 <= 1 步）。

### 题面草稿 C（`rubric`，10 分制）
> **Airbnb · Principal Engineer, AI Operations Platform（50 分钟）**
> 你要把客服与信任安全（Trust）侧的 12 个 agent 试点（退款处理、房东审核、欺诈复核、政策问答）统一到一套编排与治理平台上。约束：涉及资金与用户隐私；日均 40 万任务；p95 完成时间 < 25s（复杂案件可异步）；单位成本目标 < $0.08；安全团队要求"任何自动动作可追溯、可撤销、可熔断"；财务要求资金类错误为零；模型端点有数据驻留限制。
> 给出：平台分层与编排原语（含状态机、预算、确认、悬挂态对账）、多 agent 拓扑判据与仲裁、成本/延迟预算与优化路线（按 ROI 排序）、纵深护栏（含红队与门禁）、可观测与回放（含错误分类与 owner）、容量与配额规划（哪层先崩）、组织治理（各业务线自助边界与平台审批线）、以及三条你会写进规范的硬红线。

**加分点**
1. 分层清晰：编排（状态机/预算/恢复）与能力（工具/检索）与治理（授权/审计/评测）三者解耦，并说明为什么这是"12 个试点不变成 12 套胶水"的前提。
2. 编排原语具体：任务状态机（含 `AWAIT_CONFIRM`/`RECONCILE`/`DEGRADED`）、步数/成本/时间/失败四类预算、无进展与循环检测、快照可恢复与幂等重放（重放不重复副作用）。
3. 拓扑判据成文：三种正当理由（上下文/权限隔离、并行收益）+ 拆分前必须给收益假设与对照基线 + 拆分后必须给仲裁者与冲突处理路径。
4. 成本按 ROI 排序并量化：先减步数与扇出（列出典型占比）→ 输入压缩与工具输出裁剪 → 前缀缓存命中（给出命中率目标与稳定性手段）→ 小模型路由与升级条件 → 蒸馏（仅对高频稳定子任务）；每步都有"如何测量"。
5. 延迟分解与异步化：关键路径分析、并行无依赖调用、复杂案件转异步 + 中间进展反馈；p95 达标路径与降级形态（超预算时输出"已知 + 需人接管"）。
6. 纵深护栏成体系：入口来源标记与不可信内容处理、工具 allowlist 与参数校验、执行沙箱与出站白名单、出口 DLP、记忆写入治理、异常行为检测（调用序列漂移）、全局 kill switch（生效延迟 ≤ 1 步）。
7. 安全有效性可证明：红队用例库（注入/越权/外带/提权）、门禁中安全项零失败、演练节奏与指标（注入成功率、越权成功率）；对齐 OWASP Agentic 风险方向并能挑出本平台最危险三条。
8. 资金零错误机制化：金额/状态决策不交给模型（确定性校验器 + 政策查询 + 阈值内自动、阈值外人审）、每日对账重放（agent 决策 vs 政策上限）、错误即自动降级对应动作类型。
9. 可观测与闭环：trace 单位是任务（含每步 token/成本/TTFT/工具码），错误五分类 + owner + SLA、尾部采样保失败、线上失败可在沙箱回放（工具桩 + 数据快照），每周失败评审产出回归用例。
10. 容量与组织：推理配额/检索 QPS/下游工具限流三层弹性与排队策略、租户公平（防单业务吃满）、自助边界（read-only 工具自助 + 自动扫描，写操作审批 + 双人）、三条硬红线的可执行检查方式（CI/网关拦截，而非文档口号）。

**不足点**
- 只有"用 LangGraph/某框架串起来"，无预算/恢复/护栏。
- 安全靠系统提示词；无沙箱与出口控制。
- 成本靠换模型，未分析步数与输入构成。
- 资金决策让模型直接给金额或解析自由文本。
- 无回放能力（线上失败无法复现），无错误分类与 owner。
- 忽略容量（推理配额、下游限流）导致上线即雪崩。
- 12 个试点各建一套（无平台原语），或反过来"平台统一"却取消业务侧自主权（无法演进）。
- 红队/安全只有口号，无指标、无门禁。
