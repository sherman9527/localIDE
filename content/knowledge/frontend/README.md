# frontend 考点矩阵（TypeScript + React 工程题）

> **定位**：只对标 senior / principal。出题时禁止"什么是虚拟 DOM""类组件生命周期顺序"这类八股；每行必须能落到**一个可自动判分的实现**或**一个有明确加分点/不足点的 10 分制主观题**。
>
> **版本前提（写题面时必须显式声明，否则判分不成立）**
> - React `19.2`（`Activity`、`useEffectEvent`，2025-10-01 发布）+ React Compiler `1.0`（2025-10-07 发布）
> - TypeScript：语言考点写 `5.7 / 5.8 / 5.9` 引入的具体 flag 名；`6.0`（2026-03-23）是"最后一个 JS 实现版本"并改默认值（`strict`、`module: esnext`、`target: 当年 ES`、`noUncheckedSideEffectImports`、`types: []`、`libReplacement: false`，移除 `target: es5`/`moduleResolution: classic`/`outFile`/`baseUrl` 等）；`7.0`（2026-07-08）为 Go 原生编译器（官方口径 8–12x），**编译器 API 尚未提供**，编辑器/工具链仍走 6.x
> - 判分环境：`web/` 用 Vite + vitest（容器内 node 24）。**类型层题目必须靠 `tsc` 真实报错/`vitest typecheck` 判分**，因此判题镜像固定停在 6.x 或 5.9，不要盲目升 7.0
> - 不假设 SSR 框架存在：`Server Components` 考点在纯 SPA 环境下**只能出 `llm-rubric`**（架构边界题），不要出成需要 next 的 code 题
>
> **判分约定**：`code` 题一律 `judgeKind: react-vitest`（组件渲染 + 断言 DOM/调用序列 + 必要的 `tsc` 类型断言），`rubric` 题 `judgeKind: llm-rubric`（rubric.points 权重合计 10，bonus/gaps 由 CLI 回填）。
>
> **JD 能力码**（出题时写进 `question.source.jds[].title`，映射见仓库 `content/jd-cache/`）
> `APL-WEB-1` 大型 React/TS 代码库的可维护性与抽象能力｜`APL-WEB-2` 前端性能与关键指标（首屏/交互延迟/内存）｜`APL-WEB-3` 并发与异步正确性（竞态、取消、幂等）｜`APL-WEB-4` 数据层与 API 契约设计｜`APL-WEB-5` 测试策略与 CI 可判分性｜`APL-BE-1` 服务端/全栈边界与协议设计｜`ABNB-WEB-1` 设计系统与跨团队组件复用｜`ABNB-DATA-1` 面向数据的前端（大数据量表格/图表渲染）。
