# sql 考点矩阵（MySQL 8.x + Redis 7.x/8.x）

> **定位**：只对标 senior / principal。MySQL 侧不考"隔离级别有哪四种"，考**代价模型、锁的真实行为、可判分的执行计划断言**；Redis 侧不考"有哪些数据结构"，考**一致性、原子性、内存与延迟预算、集群约束**。
>
> **版本前提（每道题的 `statement` 里必须写死，否则判分口径不成立）**
> - MySQL：语言与语法基线为 **8.0**（窗口函数/CTE/JSON_TABLE/hash join/`EXPLAIN ANALYZE` 全部可用），生产口径为 **8.4 LTS**（2024-04-30 发布，LTS），**8.0 已在 2026-04 前后退出 Oracle 支持** → 8.0→8.4 的破坏性变化本身就是senior 考点。
> - 判题容器（见 `docker/Dockerfile` 规划：ubuntu:22.04 + apt `mysql-server`）实际装的是**发行版自带的 8.0.x**，不是 8.4。因此：凡依赖 8.4 专有语法（`RESET BINARY LOGS AND GTIDS`、tagged GTID、`FLUSH_PRIVILEGES`、`explain_json_format_version`）的题目 **只能出 `llm-rubric`**，或把题面写成"在 8.4 上这条语句会怎样"并让候选人给出 8.0 等价写法（`code` 判 8.0 可执行部分）。出题前先在容器里跑 `SELECT VERSION();` 固定基线。
> - Redis：计划镜像同样来自 ubuntu:22.04 的 apt `redis-server`（jammy 是 **6.0.x**），而考点要求 Functions(7.0)、hash field TTL(7.4)、Redis 8 统一发行版。**必须由 `docker/mirrors.sh` 走 Redis 官方 APT 源固定 7.2/7.4/8.x**，否则以下题目在容器里编译不出：`FUNCTION LOAD`/`FCALL`、`SINTERCARD`、`LMPOP/ZMPOP`、`COPY`、`HEXPIRE/HPERSIST`、`HGETEX/HSETEX/HGETDEL`、`XDELEX/XACKDEL`、`BITOP DIFF/ANDOR`、`CLUSTER SLOT-STATS`。出题前跑 `redis-cli -v` 与 `INFO server` 固定基线，并把"该命令需要的最低版本"写进题目 `tags`。
> - 判分：`mysql` runner = 建临时库 → 灌 fixture → 执行候选人 SQL 脚本 → 断言结果集/受影响行数/`EXPLAIN` 输出；`redis` runner = 灌 fixture → 执行命令序列 → 断言回复/键状态/`TYPE`/TTL。
>
> **`code` 题的确定性红线（写用例前必读）**
> 1. 任何 `SELECT` 结果集**必须有全序 `ORDER BY`**（含并列值时的决定性列），否则 MySQL 不保证行序 → 判分随机失败；
> 2. 禁止 `NOW()`/`RAND()`/`UUID()`/自增值参与期望值比较（改用注入常量或固定 seed 的 `RAND(1)`——MySQL 的 `RAND(n)` 是可复现的）；
> 3. 涉及 `EXPLAIN` 的断言只断"访问类型/是否用索引/`rows` 上界"这类稳定字段，**不断绝对 cost/时间**（`EXPLAIN ANALYZE` 的实际耗时受容器负载影响，只能做 `rubric`）；
> 4. 断言 collation/字符集时显式写 `SET NAMES utf8mb4 COLLATE utf8mb4_0900_ai_ci`（8.0 默认）而不是依赖 session 默认；
> 5. Redis 判分前后各跑一次 `FLUSHDB`（判题库单独 `SELECT <n>`），并断言"没有遗留 `TTL=-1` 的垃圾键"。
>
> **JD 能力码**：`APL-BE-2` 数据建模与查询层优化（Apple/Airbnb 后端 JD 的 "strong SQL / data modeling / query tuning"）｜`APL-BD-1` 大规模数据处理与管道性能（大数据 JD 的 "pipeline scalability / cost"）｜`APL-BE-1` 高可用与一致性（复制、故障转移、缓存一致性）｜`APL-BE-3` 存储引擎与运行时机制深度（InnoDB/Redis 内核行为）｜`ABNB-BE-2` 生产可靠性（可观测、变更安全、事后可复盘）｜`ABNB-DATA-1` 分析型 SQL（窗口/漏斗/留存，Airbnb 数据平台 JD）。
