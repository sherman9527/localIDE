# algorithms 考点矩阵（答题语言只有 Java）

> **定位**：只对标 senior / principal。题目要能区分"刷过 300 题的 5 年"与"能把实现细节、复杂度证据、对抗用例说清的 10 年"。区分手段不是题型刁钻，而是**Java 语义细节 + 复杂度证据 + 判分用例的对抗性**。
>
> **版本前提（必须在题面 `runner` 字段里钉死）**
> - 目标语言级别：Java **21**（LTS：record patterns、pattern matching for `switch`、sequenced collections、virtual threads）与 Java **22**（unnamed variables `_`、`java.lang.foreign` 转正）。Java **25**（2025-09 起的下一个 LTS）新增：JEP 502 Stable Values (Preview)、503 移除 32-bit x86 端口、505 Structured Concurrency (Fifth Preview)、506 Scoped Values (Final)、507 Primitive Types in Patterns (Third Preview)、511 Module Import Declarations、512 Compact Source Files and Instance Main Methods、513 Flexible Constructor Bodies、519 Compact Object Headers (Final)、521 Generational Shenandoah (Final) 等。**注意**：`String Templates`（21 的 JEP 430 preview / 22 的 JEP 455 second preview）已被**撤回**，25 里不存在 `STR."..."`。
> - 仓库判题镜像当前规划为 apt 的 `openjdk-17`（见 `docs/superpowers/plans/2026-09-19-daily-interview-arena.md` Task 3）。**17 编译不了 record pattern / `SequencedCollection` / `_` unnamed**，因此：凡考点落在 21+ 语法，题目必须声明 `runner: { release: 21 }`（或 22），并把 `docker/Dockerfile` 的 JDK 换成 21/22（apt 不可用时用 Temurin tar.gz）；否则只能出"17 等价写法"版本。**每个考点都提供 17 兼容解法**，判分以"结果正确 + 用例通过"为准，不因语法版本扣分。
> - 判分：`java-junit`（`javac` 编译 → JUnit 5 standalone console 执行 → 解析 `TEST-*.xml`）。`javac` 失败 = `status:'error'` 并回传前 20 行报错。
>
> **判分工程约束（写用例前必读）**
> 1. **禁止用墙钟时间证明复杂度**（容器抖动、共享 CPU）。复杂度用"可观测计数"证明：注入计数接口（`Counter`/`SpyList`）、限制 `@Timeout`（Jupiter `@Timeout` 或 `junit.jupiter.execution.timeout.default`）作为兜底、或用**规模上界**（`n=2e5` 且要求 O(n log n)，暴力必然超用例时限）+ 显式 `@Timeout(5s)` 组合。
> 2. 输出确定性：涉及顺序的返回一律要求"升序"或"按输入顺序"；不允许依赖 `HashMap` 迭代顺序；`Locale.setDefault(Locale.ROOT)`（否则 `%d`/`String.format` 与 `toUpperCase()` 在 tr_AZ 类 locale 下行为不同）。
> 3. 大输入用 `String`/`int[]` 直接注入（题目不走 stdin）；若某题要求 I/O，则给"自定义 fast scanner（`BufferedInputStream` + 手写 nextInt）"的加分点。
> 4. 递归深度类用例必须显式声明栈前提：默认线程栈下 ~1e4~1e5 层递归会 `StackOverflowError`，题目要求"迭代实现或自建栈"，否则该用例只作为"principal 附加题"。
>
> **JD 能力码**：`APL-BE-2` 扎实的数据结构与算法实现/复杂度分析｜`APL-BE-3` Java 语言与 JVM 深度（内存模型、GC、集合实现）｜`APL-BE-1` 高并发/低延迟服务的实现权衡｜`APL-BD-2` 大数据场景下的可扩展性与内存预算｜`ABNB-BE-2` 生产级代码正确性（边界、失败模式、可测试性）。
