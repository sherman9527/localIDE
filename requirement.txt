下面是具体项目场景：
1. 这是 一个本地 每日答题/刷题 系统，主要是 给我自己本地 启动以后 类似于 leetcode + 多邻国 这样的 游戏 刷题体验。
2. 游戏 主要 提供不同的 技术栈，包括前端题(TS/react）， 算法题(only java), sql 题 （mysql, redis）,系统设计题，大数据处理题（pyspark/flink/olap），agent 设计，高频面试题（显示来源公司） 。
3. 游戏为 每日挑战模式，进入 今日挑战 以后，可以 选择 当天的 技术栈开始答题。
4. 对于 以结果为导向的 题目 比如算法题，应该 提前给足 测试用例，只看 结果， 如果 错误 应该给点提示，比如 pass 多少用例， 多少没pass，失败的 用例是哪个。
5. 项目全程 都在 当前文件夹下面建立，尽可能没有其他的 依赖在其他 目录下面， 包括 docker 的镜像下载。
6. 我们有很多的 技术栈，但是只有一个 镜像，这意味着你得 安装不同 技术栈的 依赖在 那个 dockerfile 里面。
7. 题库系统和 游戏问答 系统解耦
8主观题，可以 依赖本地 的 cli 来 问答 （优先 qodercli， 其次 copilot， 都已经 安装并且login 了），把结果 展示到 网页上，比如： 满分10分，得分8， 加分点是什么， 不足的 地方是什么
9. 题库系统 主要 依赖 搜索 open 的JD 和 历史 企业高频问答题来 整理。 请提供脚本 来 刷新 题库，只增不减，题目要有 入库时间 和 最好有的 对应的 JD来源。 优先 搜索 apple 上海/美国 的 大数据工程师/后端 工程师，以及 airbnb 的 上海/美国 的 大数据工程师/后端 工程师， 你来出题第一版 题目。后续应该 依赖本地 的 cli 来 新增题库（优先 qodercli， 其次 copilot）
10. 每个 题目 应该有 移除按钮，移除以后不再展示。
11. 本项目 只 对标 senior/principal level 的 engineer 知识点
12. 本项目 应该要 考虑 最新的技术 ，而不是 只提供老的 八股文和 重复出现的 算法题
13. 项目 完成前 你应该是E2E测试过的
14.第一版先准备一个月的   面试题， 每个类别 不少于 3道题。
15. 创建 git ，做好版本控制
16. 多agent 协同工作，创建PM agent 把我产品方向， 创建 worker agent 负责写code，创建 review agent 负责 评审代码 和修复 bug。
17. 答题界面应该是 react 写的，极致，不卡顿，用户体验好，颜色不要太深。
18 系统 应该可以 判定 react 代码，Java 代码， spark 代码，pyspark 代码， mysql 代码，redis 代码 等。
19 建议是 先完整的 整理 JD 所需 技术栈的 完整知识库，再来创作 题库。
20. 游戏应该要有启动 脚本。
